## ADDED Requirements

### Requirement: 单连接内多轮对话上下文累积

系统 MUST 让同一 WS 连接内的连续多轮对话共享同一份对话上下文（含助手回复与工具调用轨迹），使模型在后续轮次能引用前文；该上下文 MUST 在连接断开后失效，不跨连接延续。

#### Scenario: 第二轮能引用第一轮内容

- **WHEN** 用户在同一连接内先问「看名字为张三的用户详情」，等待回复完成后追问「他的电话是多少」
- **THEN** 第二轮请求的模型上下文包含第一轮的用户消息与助手回复（以及工具调用轨迹），模型无需重新询问谁是"他"

#### Scenario: 新连接不带旧对话

- **WHEN** 连接断开后重新建立连接并发送首条消息
- **THEN** 该轮模型上下文不含上一个连接的任何用户消息、助手回复或工具调用轨迹

### Requirement: 每轮投影最新页面上下文

系统 MUST 在**每一轮**模型请求前注入当时最新的页面上下文（manifest 页面清单与规则、当前页可用方法、最近页面观察），且该投影 MUST NOT 作为历史消息写入对话轨迹。

#### Scenario: 切页后下一轮立即生效

- **WHEN** 用户在会话内导航到 `user-detail` 并触发页面观察，然后发送下一条消息
- **THEN** 该轮投影中的「当前页可用方法」为 `user-detail` 的方法，且包含最新观察结果

#### Scenario: manifest 热重载后下一轮生效

- **WHEN** 服务端 manifest 被重新加载（本地 mtime 变化或远程刷新），随后用户在同一连接内发送消息
- **THEN** 该轮投影使用新 manifest 的页面清单与规则，无需重建会话或重连

#### Scenario: 投影不写入轨迹

- **WHEN** 连续多轮中页面上下文发生变化
- **THEN** runtime 的对话轨迹中不因投影而新增重复的上下文消息（投影只作用于当次 provider 请求）

### Requirement: 同一会话禁止并发 run

系统 MUST 保证同一会话同时最多只有一个 agent run 在执行；运行期间收到新的 `chat.send` MUST 被拒绝并明确告知用户，而不是启动第二个 run。

#### Scenario: 运行中再次发送被拒绝

- **WHEN** 某会话的 run 仍在执行（流式输出未结束）时，用户再次发送消息
- **THEN** 服务端不启动第二个 run，并回 `chat.error`（说明上一轮仍在进行中），用户可在本轮结束后重发

### Requirement: 取消当前 run 后会话可继续

系统 MUST 支持用户取消当前 run，取消后同一会话 MUST 仍可继续多轮对话。

#### Scenario: 取消后进行下一轮

- **WHEN** run 执行中用户发送 `chat.cancel`
- **THEN** 当前 run 被中止并回 `chat.done`，随后用户发送新消息可正常得到回复，且新一轮仍带取消前的对话上下文

### Requirement: 对话上下文有界裁剪

系统 MUST 对注入模型的对话上下文做有界裁剪，避免长对话导致每轮 token 无界增长；裁剪 MUST 保留完整的系统提示（角色与规则），且 MUST NOT 把成对的工具调用与工具结果截断为不合法序列。

#### Scenario: 超出预算时裁剪早期消息

- **WHEN** 连接内对话消息数超过配置上限（默认 24 条）
- **THEN** 投影中只保留最近若干条消息，且 systemPrompt 完整保留

#### Scenario: 工具调用与结果成对保留

- **WHEN** 裁剪边界落在工具调用与其结果之间
- **THEN** 投影结果中不出现孤立的工具调用或孤立工具结果（成对保留或成对丢弃）
